since-clock

Five shells. One engine.

One .js file, one .css file, no dependencies, no build step. Every frame is Date.now() - start — nothing is ever incremented, so no frame it paints is ever wrong. The shells below are five different objects built on that one computation, not five skins on one object.

Left completely alone, fallback intact, no underline. A clock that cannot tell the time should say nothing, not NaN.

The idea

const elapsed = Date.now() - start;

Nothing is ever incremented and nothing animates toward a value. There is no accumulator, so there is no first frame showing zero, no drift, and no catch-up after the tab was hidden. Miss a thousand frames and the next one is still exactly right.

Scrub is the same idea one level up. Flow mode reads a fractional second nobody asked for and holds the wheel there; scrub reads a fractional day you pick, by dragging across the element, and shows the elapsed time as of that instant. Both exist because the engine was never "the time since start, ticking" — it was always "the time between start and any instant," and the instant only had to stop being hardcoded to now. A setInterval clock cannot do either, because it never knows more than the ticks it has counted.
